# Tool-choice eval, 2026-10-22: fewer tools per request

What changed (docs/fewer-tools-contract.md): a ceiling of 15 tools per request
(least recently used section put away), installed skills folded into one
`skills` tool, `schedule_update` folded into `agents` and the projector into
`media`, and (tried, then removed) one example call per merged action.

## How it was measured

`scripts/tool_eval.py` with `tests/fixtures/tool_eval/cases.yaml`: 44
operator-style prompts that each need one specific tool, covering every
section, skills, two local chats and four "ceiling" cases (four sections
already loaded, the tool in a fifth). Real registry, real `View`, real model:
DeepSeek V4.1 Flash on the test box, the configured temperature (0.7), thinking
as production has it. A case runs up to 4 tool calls (stub results in between,
at most 2 `tools()` loads) and is correct when the expected tool is called.
Three repeats per case (132 runs per arm). Run beside the live service from
`~/tool-eval/` with throwaway state dirs; nothing deployed.

## Results

| arm | right tool within 4 calls | first try | args right | most tools in a request | mean prompt tokens |
|---|---|---|---|---|---|
| before (main 3e860ac presentation) | 77.3% | 47.7% | 100% | 16 | 14,102 |
| ceiling + folds, no examples | 80.3% | 46.2% | 98.1% | 15 | 13,663 |
| ceiling + folds + examples | 78.8% | 48.5% | 98.1% | 15 | 14,273 |

The same "before" code scored 81.1% on an earlier run of the same cases, so
run-to-run noise is about ±3 points: the three arms are equal on accuracy.

- The ceiling and the folds meet the 15-tool limit at no measurable cost, with
  slightly smaller prompts. Shipped.
- Per-action examples bought nothing measurable (DeepSeek already gets ~98-100%
  of arguments right) for ~4.5% more prompt tokens. Removed; the `example:`
  plumbing stays for a tool the model fumbles (tests/test_tool_examples.py
  checks any that are added).
- One regression was found and fixed on the way: with skills folded, the
  `tools` listing said only `skills`, and a skill went unfound (skill-weather
  3/3 -> 0/3). The listing now names each skill (`list_actions`).

## Limits

- Stub results: a task that needs a real file's content (edit-file) cannot
  finish; it scores low in every arm alike.
- 44 cases x 3 repeats: differences under ~4 points are noise.
- The ceiling cases test finding a fifth section's tool, not coming back to a
  section that was put away; that path is covered by tests, not this eval.
- Cost of the three runs: about $0.95 at list price (cache hits not counted).

## Re-running

```sh
# on a host with the model key (the test box): a copy of the tree, a throwaway state dir
set -a; . ~/.config/jarvis/env; set +a
JARVIS_STATE_DIR=/tmp/eval-st python scripts/tool_eval.py --repeat 3 --out run.jsonl
python scripts/tool_eval.py --compare before.jsonl run.jsonl
```
